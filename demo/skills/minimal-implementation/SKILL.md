# 最小改动实现

## 概述

方案确认后，本技能管理实现阶段。核心原则是**最小代码量、最大清晰度**：严格实现方案规定的内容，用最小的必要改动，同时保持代码结构清晰可维护。

## 何时使用

**适用场景：**
- 方案已经用户确认，开始编码
- 实现方案中规定的任何功能、修复或变更

**不适用：**
- 编写方案本身（使用 `plan-before-code`）
- 调试或排查错误（使用 `problem-tracking`）
- 编写交付说明（使用 `delivery-checklist`）

## 流程

### 第一步：重新阅读已确认方案

在接触任何代码之前，重新阅读已确认的方案文档。确认：
- 文件范围（哪些要新增、修改、不碰）
- 实现流程
- 模块职责

### 第二步：严格按方案实现

实现过程中遵守以下规则：

1. **只修改方案中列出的文件。** 如果发现需要修改方案外的文件，停下来，先更新方案，再重新确认。

2. **最小代码量。** 优先局部修改而非重写。够用一个函数就不新建一个类。能复用已有代码就不重复写。

3. **不添加未确认的功能。** 不擅自增加方案中没有的功能、接口、协议、数据结构、依赖库或配置项。

4. **不做无关重构。** 不"顺手清理"相邻代码，不删除你不理解的注释，不重构与任务无关的系统。

5. **保持分层架构。** 代码放在正确的层（详见 `references/code-layers-reference.md`）：
   - UI 层：仅负责显示和交互
   - Service 层：生命周期管理
   - Logic 层：业务流程
   - Comm 层：通信
   - Data 层：数据处理
   - Config 层：配置
   - Utils 层：通用工具

### 第三步：自查代码结构

在宣布实现完成之前，确认：
- 每个文件职责单一明确
- 文件名能体现用途
- 没有把 UI + 通信 + 解析 + 存储混在一起的"万能文件"
- 主要文件、类、函数有 Doxygen 注释
- 调用关系简洁

## 代码分层速查

详细分层规则见 `references/code-layers-reference.md`。

**有 UI 的项目：**
```
ui/       → 显示、交互、状态展示、日志展示
logic/    → 业务流程、功能调度、状态判断
comm/     → 通信（CAN、串口、TCP、WebSocket 等）
data/     → 数据模型、解析、缓存、存储
config/   → 默认参数、配置加载/保存
utils/    → 时间、文件、字符串、日志辅助
```

**纯后端项目：**
```
service/  → 启动、生命周期、信号处理
logic/    → 业务流程（同上）
comm/     → 通信（同上）
data/     → 数据处理（同上）
config/   → 配置（同上）
utils/    → 通用工具（同上）
```

**后端程序不需要强制加 UI**，重点做好日志、配置和状态输出。

## 常见借口与反驳

| 借口 | 事实 |
|------|------|
| "顺便把相关模块也重构一下" | 未经授权的重构会引入新 bug 并违反已确认的范围。如需重构，另写方案。 |
| "这个小功能加上去会很有用" | "有用"不等于"被要求"。每个未经确认的增加都是未测试、未文档化的未来维护负担。 |
| "现有代码太乱了，我清理一下" | 清理与任务无关的代码有破坏正常功能的风险，且产生未经审核的变更。 |
| "我加个更灵活的架构方便以后扩展" | YAGNI（你不会需要它）。"以防万一"的复杂架构增加了维护成本却没有证明价值。 |
| "多加几个依赖没关系" | 每个新依赖都是安全、兼容性和维护的负担。 |
| "这个改动很简单，不用查方案" | 再简单的改动放错文件或层级也会出问题。方案定义了范围——照做。 |

## 危险信号

- 修改了已确认方案中未列出的文件
- 增加了方案中没有的功能、协议或配置项
- 作为副作用重构了相邻代码
- 未经方案批准引入了新依赖
- 创建了混合多种职责的"万能文件"
- 使用了模糊、无描述性的文件名
- 公共接口缺少 Doxygen 注释

## 验证

实现完成后：

- [ ] 只修改/创建了已确认方案中列出的文件
- [ ] 没有添加未确认的功能
- [ ] 改动使用了最小代码量（无多余抽象或重复）
- [ ] 代码放在正确的层（UI/logic/comm/data/config/utils/service）
- [ ] 每个文件职责单一明确
- [ ] 主要文件、类、函数有 Doxygen 注释
- [ ] 项目编译成功（如适用）
- [ ] 现有功能未被破坏（基本冒烟测试通过）
