# 使用开发工作流

## 概述

本项目将结构化开发工作流定义为技能。每个技能编码了一个必须遵循的特定流程——先写方案再编码、最小改动实现、问题追踪记录、交付检查清单。本元技能帮助你发现并应用当前任务对应的正确技能。

## 技能发现

当任务到达时，识别开发阶段并应用对应技能：

```
任务到达
    │
    ├── 需要明确需求？ ──────────────→ plan-before-code
    ├── 需要编写实施方案？ ──────────→ plan-before-code
    ├── 用户已确认方案？ ────────────→ minimal-implementation
    ├── 正在写代码？ ────────────────→ minimal-implementation
    ├── 遇到编译/运行错误？ ─────────→ problem-tracking
    ├── 遇到 bug 或异常行为？ ───────→ problem-tracking
    ├── 需要记录已解决的问题？ ──────→ problem-tracking
    ├── 功能完成，准备交付？ ────────→ delivery-checklist
    ├── 需要写交付说明？ ────────────→ delivery-checklist
    └── 不确定该用哪个技能？ ────────→ 优先读 plan-before-code
```

## 核心操作行为

以下行为在所有技能中、任何时候都必须遵守，不可商量。

### 1. 暴露假设

在实现任何非平凡任务之前，明确陈述假设：

```
当前假设：
1. [关于需求的假设]
2. [关于架构的假设]
3. [关于范围的假设]
→ 如有错误请现在纠正，否则我将按这些假设继续。
```

### 2. 主动管理困惑

当遇到不一致、需求冲突或规格不清时：
1. **停下来。** 不要靠猜测继续。
2. 明确指出具体困惑。
3. 提出权衡或澄清问题。
4. 等待解决后再继续。

### 3. 必要时据理力争

当某个方案有明显问题时，直接指出问题，解释具体负面影响，并提出替代方案。逢迎是失败模式。

### 4. 强制简洁

在完成任何实现之前，问自己：
- 能用更少的代码行完成吗？
- 这些抽象值得它们的复杂度吗？
- 资深工程师看了会说"为什么不直接……"吗？

### 5. 保持范围纪律

禁止：
- 删除你不理解的注释
- "顺手清理"与任务无关的代码
- 作为副作用重构相邻系统
- 因为"看起来有用"而添加方案外的功能

### 6. 验证，不假设

任务在验证通过之前不算完成。"看起来没问题"永远不够——必须有证据（测试输出、构建结果、运行数据）。

## 技能规则

1. **开始工作前先检查是否有适用技能。** 技能编码了能防止常见错误的流程。
2. **技能是工作流，不是建议。** 按顺序执行步骤。不要跳过验证步骤。
3. **多个技能可以组合使用。** 一个功能可能涉及 `plan-before-code` → `minimal-implementation` → `problem-tracking` → `delivery-checklist` 的顺序执行。
4. **不确定时从方案开始。** 如果任务不平凡且没有方案，从 `plan-before-code` 开始。

## 需要避免的失败模式

1. 未经检查就做出错误假设
2. 不管理自己的困惑——迷失时硬冲
3. 注意到不一致却不提出来
4. 在非显而易见的决策上不给出权衡
5. 对有明显问题的方案逢迎附和（"当然可以！"）
6. 过度复杂化代码和 API
7. 修改与任务无关的代码或注释
8. 删除不完全理解的东西
9. 因为"很明显"而不写方案就开始构建
10. 因为"看起来没问题"而跳过验证

## 生命周期顺序

对于一个完整功能，典型的技能顺序是：

```
1. plan-before-code          → 明确需求，编写实施方案
2. [用户审核 + 确认]
3. minimal-implementation    → 严格按确认的方案实现
4. problem-tracking          → 记录实现过程中遇到的问题
5. delivery-checklist        → 自测、写交付说明、交付
```

不是每个任务都需要所有技能。一个简单的修复可能只需要：`plan-before-code` → `minimal-implementation` → `delivery-checklist`。

## 危险信号

- Agent 在没有检查适用技能的情况下就开始实现
- Agent 跳过方案步骤直接写代码
- Agent 添加了确认方案中没有的功能
- Agent 做了与任务无关的大范围重构
- Agent 没有记录遇到的问题
- Agent 交付时没有交付说明

## 验证

完成任何技能流程后，确认：

- [ ] 在开始工作前已识别适用技能
- [ ] 所有技能步骤已按顺序执行
- [ ] 没有跳过任何步骤
- [ ] 具体技能的验证清单已完成
- [ ] 所有证据要求已满足（测试输出、构建结果等）
