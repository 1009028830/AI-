# AGENTS.md

本文件为 AI/开发助手提供项目级别的执行指导。详细工作流定义在 `skills/` 目录，参考模板在 `references/` 目录，权威参考文档在 `docs/process/`。

---

## 仓库概览

本项目为 SDK 开发模板，采用技能驱动工作流模式。Agent 必须通过技能文件入口执行任务，而非直接跳入编码。

---

## 核心规则

- **技能优先：** 在开始任何工作前，必须检查是否有适用技能（即使只有 1% 可能性），技能位于 `skills/<skill-name>/SKILL.md`
- **技能是工作流，不是建议：** 必须严格按技能步骤执行，不可跳过、不可部分执行
- **永远不要在无方案时直接写代码：** 任何非平凡任务必须经由 `plan-before-code` 技能

---

## 意图 → 技能映射

| 任务类型 | 适用技能 |
|---------|---------|
| 新功能 / 功能修改 / Bug 修复 / 重构 | `plan-before-code` → `minimal-implementation` |
| 配置、脚本、部署方式修改 | `plan-before-code` → `minimal-implementation` |
| 协议字段、默认参数、通信行为修改 | `plan-before-code` → `minimal-implementation` |
| 文档结构调整、大范围重写 | `plan-before-code` → `minimal-implementation` |
| 编译/运行/通信异常 | `problem-tracking` |
| 功能实现完成，准备交付 | `delivery-checklist` |
| 不确定该用哪个技能 | `using-dev-workflows`（元技能） |

---

## 生命周期映射

Agent 必须按以下生命周期处理每个任务：

```
DEFINE  → `plan-before-code`        需求理解 + 方案编写 + 用户审核
  ↓ [用户确认]
BUILD   → `minimal-implementation`  严格按方案编码，最小改动
  ↓ [遇到问题]
VERIFY  → `problem-tracking`        记录现象 → 定位原因 → 写入 development_memory
  ↓ [实现完成]
REVIEW  → `delivery-checklist`      自测 → 写交付说明 → 检查清单
SHIP    → 向用户呈现交付说明
```

---

## 执行模型

每次收到任务请求：

1. 判断是否有适用技能
2. 调用对应技能的完整工作流
3. 严格遵循技能步骤（不跳过、不部分执行）
4. 只有在所需阶段（方案确认、编码、测试、交付）完成后，才进入下一阶段

---

## 反规避

以下想法是错误的，必须忽略：

| 错误想法 | 正确行为 |
|---------|---------|
| "这个改动太小，不需要方案" | 小改动同样需要方案。5 行方案永远比错误假设的调试成本低。 |
| "我可以先快速实现再说" | 先写方案，等用户确认。跳步是返工的第一原因。 |
| "我先收集上下文，不用走技能" | 技能工作流本身包含了上下文收集步骤。不冲突。 |
| "这个看起来很简单" | "看起来简单"往往是"有隐藏假设"。方案能暴露它们。 |
| "我顺便把这个也修了" | 只做方案规定的范围。额外修改需要新方案 + 重新确认。 |

正确行为：始终先检查并调用合适的技能。

---

## 修改边界

- 只做用户明确要求的内容，严格按已确认方案执行
- 采用最小改动完成目标（能复用不重复、能局部不大改）
- 不擅自增加新功能、新协议、新数据结构、新依赖或新配置项
- 不做无关重构：不修改方案外文件；若必须修改，先更新方案并再次确认
- 不删除历史文档、历史快照或用户已有改动

## 文件结构

```
skills/         技能工作流（Agent 执行入口，按需加载）
references/     参考模板（方案模板、问题记录模板、交付格式、代码分层参考）
docs/
  INDEX.md      文档索引
  development_memory.md   长期问题记录（每次开始前必读）
  process/      开发流程规范（权威参考，Agent 优先走 skills/）
  history_plans/  历史方案归档
  usage/        使用说明
  deploy/       部署说明
  protocol/     协议资料
src/            源码
include/        头文件
scripts/        脚本
config/         配置
tests/          测试
```

根目录和 `docs/` 顶层只保留入口型文档。

## 环境约束

复制模板后按新项目实际填写：

```text
开发环境：
目标运行环境：
可在本机验证的内容：
必须在目标环境验证的内容：
```

交付时不能把静态检查说成目标环境实测。
