# 文档整理说明

## 1. 整理目的

本项目文档按用途分类，目标是让使用、部署、协议、历史方案和开发规范互相分离。

## 2. 推荐阅读顺序

新接手项目时建议按以下顺序阅读：

1. `README.md`
2. `docs/INDEX.md`
3. `docs/项目代码结构与使用说明.md`
4. `docs/development_memory.md`
5. 与当前任务相关的 `docs/usage/` 使用说明或 `docs/history_plans/` 历史方案

部署时建议优先阅读：

1. `README.md`
2. `docs/项目代码结构与使用说明.md`
3. `docs/deploy/` 中的部署说明

排查问题时建议优先阅读：

1. `docs/development_memory.md`
2. `docs/项目代码结构与使用说明.md`
3. 对应模块的 `docs/usage/` 使用说明
4. 对应模块的 `docs/history_plans/` 历史方案

## 3. 当前目录分类

| 目录 | 内容 | 使用方式 |
|---|---|---|
| `../skills/` | 技能工作流（Agent 执行入口） | Agent 按任务类型自动选择 |
| `../references/` | 参考模板（方案、问题记录、交付格式、代码分层） | 技能工作流按需引用 |
| `docs/` | 索引、结构说明、整理说明、长期问题记录 | 优先阅读 |
| `docs/usage/` | 当前使用说明和模块说明 | 可作为操作依据 |
| `docs/deploy/` | 部署、自启动、环境说明 | 部署时阅读 |
| `docs/history_plans/` | 历史方案、开发方案、修复方案 | 作为变更背景 |
| `docs/protocol/` | 字段、接口、通信标准资料 | 协议依据 |
| `docs/process/` | 开发流程规范（权威参考，Agent 优先走 skills/） | 人工查阅参考 |

## 4. 后续维护规则

1. 当前可执行操作写入 `docs/usage/`，不混入历史方案。
2. 部署和环境配置写入 `docs/deploy/`。
3. 方案文档写入 `docs/history_plans/`。
4. README 只写快速入口，不堆详细逻辑。
5. `docs/INDEX.md` 每新增一个重要文档都要更新索引。
6. 发现已确认问题时，更新 `docs/development_memory.md`。
7. 默认地址、设备 ID、端口号应以当前代码为准，并标明是否可配置覆盖。
