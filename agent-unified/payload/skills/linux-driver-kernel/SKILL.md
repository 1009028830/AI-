# Linux 驱动与内核开发

以目标源码树及子系统约定为基线，区分源码分析、构建检查、受控测试和真实设备运行。

## 定位目标与模式

- 确认 kernel tag/commit、厂商 BSP 补丁、ARCH、交叉工具链、配置、构建输出目录、设备树和目标板修订。运行中的内核与源码/配置不一致时先说明差异。
- 阅读相关子系统实现、Documentation、MAINTAINERS、Kconfig/Makefile、调用方和测试；驱动问题还需对应设备数据手册与原理图，不用 latest API 猜测旧 BSP 行为。
- 驱动任务聚焦 probe/remove、设备资源和子系统契约；内核核心任务另查对象生命周期、锁序、RCU、内存模型及 UAPI。只加载与变更相关的分支。
- 保持 Kernel Coding Style 和所在子系统习惯，不自动用用户态格式配置重排整个内核文件。

## 关键审查点

| 范围 | 要核对的内容 |
| --- | --- |
| 上下文与锁 | 每个入口所处进程、硬中断、线程化中断、原子或其他上下文，是否允许睡眠；锁序、抢占配置与 PREEMPT_RT 差异 |
| 设备生命周期 | probe 失败回收、延迟探测、remove/热拔插/挂起；先停止硬件和异步访问，再释放被访问对象 |
| 托管资源 | devm_* 的释放时机与引用/并发独立分析；自动释放不证明工作队列、中断和 DMA 已停止 |
| MMIO 与 DMA | 使用适合架构/设备的 accessor 和 DMA API，分清 CPU 地址与 DMA 地址、方向、映射/解除及缓存同步 |
| 并发对象 | 引用计数、RCU 读侧与回收期、回调取消同步、定时器/工作队列退出；READ_ONCE/WRITE_ONCE 不替代完整同步协议 |
| UAPI | 用户指针访问、结构体填充与初始化、固定宽度、32/64 位兼容、错误语义和 ABI 稳定性；不泄露内核数据 |
| 设备树 | binding/schema、compatible 与资源描述符合硬件；不为绕过驱动问题随意改已有稳定 binding |

分析失败路径与并发交错，定位具体源码行和触发条件；不把 checkpatch 通过当成内存安全或并发正确的证据。

## 匹配风险的验证

1. 用项目固定内核配置和工具链构建受影响模块/子系统。外置模块使用正确的构建输出树；不能默认宿主 `/lib/modules/.../build` 就是目标内核。
2. 按任务运行源码树自带的 checkpatch、编译警告检查；有环境时使用 Sparse/Smatch。设备树改动选择 dt_binding_check/dtbs_check；工具缺失则记录，不把未运行写成通过。
3. KUnit、kselftest、子系统测试和 lockdep/KASAN 等按变更与测试内核支持选择，避免直接开启在生产内核造成不受控开销或重启。
4. 加载模块、绑定/解绑、写 sysfs、寄存器访问、换内核或触发故障之前核对目标与动作授权；具备必要的控制台、旧内核/模块和恢复路径。安全条件不足时只交付已完成的源码/构建工作及测试方案。
5. 在已授权测试目标上检查正常、初始化失败、并发访问、卸载/断连和必要电源管理路径，记录 dmesg、版本及测试结果。任何故障停止条件由当前系统约束确定，不沿用其他板卡阈值。

交付说明目标内核、配置、补丁范围、接口兼容性、执行证据和待验证项。生成补丁不自动授权发邮件、提交上游或修改生产系统。
