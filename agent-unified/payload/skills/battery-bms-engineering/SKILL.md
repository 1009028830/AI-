# 新能源电池与 BMS 工程

处理电池控制软件及软硬件协同，先确定动力电池、固定式储能或其他工业场景。规则和资料可在 Windows/Linux 使用；仪器、AFE、目标板和仿真工具分别验证。

## 建立电池与系统基线

读取化学体系、供应商型号及规格版本、串并联拓扑、额定与允许工作范围、AFE/MCU、采样链、电流与温度传感器、接触器/熔断器、预充与绝缘监测电路、供电/唤醒路径和通信协议。

确认测量符号与单位、保护阈值及公差、允许动作、故障等级/优先级、反应时间、恢复条件、单点故障假设。缺少安全关键参数时继续架构/离线分析，暂停依赖这些参数的动作与定值结论。

## 任务路由

- 开发算法、驱动、状态机和保护：读取 [工程规则](references/engineering-rules.md) 对应部分。
- 标准选型与版本更新：读取 [规范与来源](references/standards.md)，区分车用、充电、储能和运输。
- 制定回归、HIL、台架和验收计划：读取 [验证矩阵](references/verification.md)。
- 车用 BMS 同时需要 ECU 网络、诊断和安全升级规则时，使用已安装的 `automotive-embedded-engineering`，无需把完整车规流程强加给非车用储能软件。

## 实施原则

1. 采样值同时携带有效性、采样时刻和诊断状态。滤波值、保护值、估算值和显示值区分使用，不能用最后正常值无限掩盖传感器故障。
2. 参数来自项目确认的电芯、系统和安全资料，记录适用温度/老化/工况、误差预算、版本及批准人。不内置“所有锂电池通用”的电压、电流、温度或预充阈值。
3. SOC/SOH/SOP 是带假设和误差的估计；电芯直接保护、硬件保护和系统保护按安全架构独立检查，不能依赖一个 SOC 数值保证安全。
4. 接触器/充电/均衡/热管理动作采用状态前提、互锁、反馈与超时。故障安全状态来自系统危害分析，不能统一写成“任何异常立即断开接触器”。
5. 离线回放、SIL/HIL 和实物验证分开。电芯滥用、短路、热失控、高压和真实充放电测试需对应授权、设施与规程；资料收集和技能安装不包含此类动作授权。
6. 参考代码接入需审查许可证、版本、单位、平台假设和故障行为，单片机示例不能直接成为量产 BMS。

## 交付

输出适用范围、信号/参数契约、受影响状态与保护链、实际验证、证据和残余缺项。新标准进入差异评估与项目适用性确认，不自动更改量产保护参数；本技能不提供认证或整包安全保证。
