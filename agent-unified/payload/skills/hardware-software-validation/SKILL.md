# 软硬件联调与验收

将协议、软件配置、物理连接和设备反馈对应到可追溯证据。按离线分析、被动观测、主动操作选择范围；已有明确动作授权持续有效，不重复询问同一事项。

## 建立最小联调契约

从当前项目资料和实际设备读取，缺失的高影响参数保留为待确认：

- 设备型号/序列号、硬件与固件版本、接口/通道、适配器及后端、连接拓扑、供电与隔离条件。
- 地址/节点 ID、波特率或位速率、帧格式、端序、符号、比例、单位、范围、更新周期及超时。
- 指令/寄存器的读写性质、状态前提、确认反馈、幂等性、失败后的状态和停止条件。
- 测量设备、采样率、时间戳来源、量程及必要校准情况；验收阈值来自合同、协议、器件资料或已确认测试规范。

先查本机实际工具与权限。若 engineering-toolbox 可用，按其当前环境报告定位工具；否则复用项目入口，不硬编码另一台机器路径。Linux SocketCAN、Windows 厂商驱动和 USB 后端分别验证。

## 分阶段推进

| 阶段 | 可做内容 | 证据与边界 |
| --- | --- | --- |
| 离线分析 | 解码日志、DBC、PCAP、寄存器表，检查协议和状态机 | 输入文件、规范版本、解析假设；不能证明物理总线正常 |
| 被动观测 | 在授权接口范围采样，核对周期、丢帧、状态和时间关系 | 保留原始数据与采样配置；“只收不发”仍须核实工具/适配器行为 |
| 受控动作 | 在已授权目标和模式下逐项发送，等待反馈、检查状态 | 发出帧、应答和最终业务状态分别记录；超时不等于动作未执行 |
| 异常与验收 | 执行已授权的断连、重连、重启及适用故障用例 | 故障注入和真实执行器动作需对应授权与安全条件；越界立即停止相关动作 |

安全相关动作包括上电、充放电、高压、保护参数修改、固件升级和执行器控制。未获相应动作授权时继续离线分析或准备测试，不发送指令试探设备状态。

## 协议和时序检查

- CAN：区分经典 CAN/CAN FD、标准/扩展 ID、位速率、过滤器、错误帧和物理连接；SocketCAN 本地回环或发送成功不等于远端设备收到，更不等于业务执行完成。
- UDS：核对寻址、会话、安全访问、服务/子功能、负响应与等待时间；读服务与写/例程/下载服务分开授权，不扫描未知 ECU 或绕过访问控制。
- 串口/Modbus：确认电平标准、帧参数、RTU/TCP、站号、地址基准与寄存器宽度；多寄存器字序和读写副作用按设备手册确认。
- 网络和控制状态机：处理重发、重复/乱序、陈旧反馈、重启后的状态恢复；仅对协议允许且安全的操作有限重试，绝不盲目重放执行指令。
- 观测对照：对齐软件日志、总线报文、示波器/逻辑分析仪及物理反馈的时间基准；同步不确定性超出容差时不能据此判定时序合格。

## 结果与恢复

每个实际用例记录目标版本、前置条件、输入/动作、预期、实测、时间范围、原始证据位置和通过/失败/未执行。发送、应答、状态到达和业务验收分别判定。

失败时保存原始日志与最后已知状态；按事先确定的安全状态和恢复步骤处理，不自动断电或反向动作。结束时清理本次创建的连接/采样任务，按约定恢复配置，不覆盖设备已有数据。

虚拟 CAN、串口回环、协议单元测试和模拟设备的结果单独标注。真实时延、电气指标、保护动作、现场验收以及 EDA/EMC/信号完整性签核都需要相应实测或专门流程。

## 资料入口

- [SocketCAN / Linux Kernel](https://www.kernel.org/doc/html/latest/networking/can.html)：2026-10-15 在线核对 Linux CAN 栈与回环语义；不能外推为 Windows 后端行为。
- UDS、Modbus 及具体控制指令使用项目指定标准版本与设备官方协议；未获得正文时注明缺项，不用网上示例补造寄存器或安全阈值。
