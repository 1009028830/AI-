# 方案参考

先按 [方案技能](../skills/plan-before-code/SKILL.md) 判断是否需要持久化。普通任务可在聊天中说明目标、范围、步骤和验收，不为使用本参考创建文件。

需要保存时，优先更新项目已有对应文档；没有合适位置时可使用 `docs/history_plans/YYYYMMDD_功能名称_开发方案.md`。下面提供内容框架和可选章节，仅保留本次确实需要的内容，不整份复制或逐项填写“不适用”。

## 简短方案框架

```markdown
# [任务名称] 方案

- 目标与验收：完成后的可观察结果，以及通过条件。
- 影响范围：涉及的模块、接口、数据及明确排除项。
- 实现步骤：必要的小步及其依赖。
- 验证方法：相关检查、执行环境和当前无法覆盖的内容。
```

已有上下文足够时直接引用，不重新抄录需求、源码说明或整段历史记录。方案的长度由关键决定和实际风险决定。

## 按需补充的内容

### 当前事实与来源

记录影响设计的现状、版本或约束，并引用权威代码、协议或文档。项目存在相关历史问题时引用记录；未读取过的资料不能写成已查阅，不为普通任务新建问题库。

### 接口与模块协作

跨模块接口需要写清职责、输入输出、单位、错误语义、超时、兼容性与调用方影响，按实际涉及项选用。沿用项目分层，不为填模板机械新增 UI、Service、Data 等层。

### 实现与失败路径

说明关键算法、状态转换、数据流及主要异常处理；简单任务可只列步骤。涉及 UI 时描述相关交互状态；涉及配置或存储时描述默认值、迁移和兼容策略。

### 高风险动作与回退

针对数据、安全、权限、真实设备、生产或破坏性操作，保留对应记录：

- 目标、前置条件、安全限制及明确动作授权。
- 兼容性和失败影响，必要的执行前检查。
- 回退触发条件、可执行步骤、数据保护与恢复后验证。
- 本地、模拟和目标环境各能证明什么，当前未验证的边界。

保存方案不会自动获得动作权限；只在已有明确授权及必要条件具备时执行。

### 验证证据

需要多项验收或交接时可采用下表；简单任务用短清单即可。

| 风险 / 验收项 | 验证方法 | 预期结果 | 验证环境 |
|---|---|---|---|
| [相关验收项] | [命令或操作] | [通过条件] | [实际环境] |

验证沿用“编译/基础检查 → 相关功能验证 → 一轮集中审查”，复用有效结果；计划不要求提前运行所有检查。

### 衔接与状态

跨会话或多人协作时记录负责人、依赖、当前状态、已完成项和下一步，需要版本区分时再记录版本及日期。实施中按实际变化更新，不逐步重复生成新文件。

### 授权与待确认事项

记录需要追溯的已有授权及覆盖范围，以及仍缺少的关键选择或动作权限。已有明确实施授权覆盖当前方案时继续；只有关键选择缺失、实质扩大范围/风险、动作未授权，或用户明确要求单独审批时，才暂停相关步骤。必要文件调整仍在同一授权目标内时更新范围说明即可。
