# 方案模板

在 `docs/history_plans/` 中创建新开发方案时，复制并填写此模板。

推荐命名：

```text
docs/history_plans/YYYYMMDD_功能名称_开发方案.md
```

---

# [功能名称] 开发方案

> 状态：Draft / Approved / Superseded / Implemented
> 版本：v1.0
> 创建日期：YYYY-MM-DD
> 授权记录：填写已有明确授权及覆盖范围；仅未覆盖事项待确认
> 风险级别：L2 / L3

## 1. 需求说明

说明本次要实现什么，以及用户明确要求和约束。

## 2. 当前现状

说明当前项目中已有的相关代码、模块、配置、文档或流程。

## 3. 历史问题参考

> 本次开发前已查看 `docs/development_memory.md`。

相关历史问题：

- [列出相关问题编号，或写“未发现相关历史问题”]

本次需要避免：

- [根据历史问题列出注意事项]

## 4. 实现目标

列出本次完成后应达到的可验证目标。

## 5. 实现原则

- 最小必要改动
- 不影响现有功能
- 结构清晰
- 严格按本方案执行
- 不增加未确认功能
- 不把未经验证的能力写成已完成

## 5.1 不做事项

- [明确排除项，防止范围蔓延]

## 6. 项目类型与接口说明

**项目类型：** 后端服务 / 命令行工具 / 前端应用 / 移动端 / 嵌入式 / 数据管道 / 其他

**是否涉及 UI：** 是 / 否

**处理方式：**

- 如果涉及 UI：列出新增视图、控件、状态、空态、错误态和响应式要求。
- 如果不涉及 UI：说明通过日志、配置、命令行、API 或状态接口体现运行状态。

## 17. 授权与待确认事项

记录当前任务中已有授权和适用范围；列出仍缺少的关键选择、动作权限或实质扩展。没有待确认事项时注明可以按已有授权继续。

推进标准：

- 已有明确实施授权覆盖当前方案时继续，不因生成新方案而要求固定措辞的重复确认。
- 授权不足或用户明确要求另行审批时，仅对对应事项等待确认；关键歧义先澄清，不能由模糊表达推定高影响动作权限。
