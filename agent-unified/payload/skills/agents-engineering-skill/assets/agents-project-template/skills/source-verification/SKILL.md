# 来源校验

## 流程

1. 从锁文件、清单或运行输出确认实际版本。
2. 优先查项目内正式协议、schema 和供应商/框架官方文档。
3. 技术问题只使用一手来源：官方文档、规范、源码或论文。
4. 获取支持当前决策的具体章节，不用搜索摘要代替正文。
5. 记录来源日期/版本，区分引用事实与自己的推断。
6. 如果官方资料与当前可运行行为冲突，报告冲突并以可复现实证约束改动。

## 输出

```markdown
### 已确认
- [结论] — [来源/版本]

### 推断
- [由来源推导但未直接声明的内容]

### 未确认
- [资料未覆盖或当前环境无法验证]
```

## 停止条件

- 关键版本无法确定。
- 只有二手文章而没有可核对的一手来源。
- 来源要求的接口变化会扩大已批准范围。

## 验证

- [ ] 版本和来源匹配当前项目。
- [ ] 关键结论有直接支持。
- [ ] 没有把搜索片段或记忆当成当前事实。
- [ ] 引用、推断与未确认内容已分开。
