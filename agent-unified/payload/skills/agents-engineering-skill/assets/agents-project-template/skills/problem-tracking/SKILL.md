# 问题追踪记录

## 流程

### 1. 查重

记录新问题前先读：

```text
docs/development_memory.md
```

如果已有类似问题，更新或引用已有条目，不重复创建。

### 2. 记录

问题解决后判断是否值得长期记录。普通拼写错误、已被测试完整表达的预期失败、无复用价值的临时输出不写入长期记忆。

符合准入条件时使用模板：

```text
references/problem-record-template.md
```

每个问题必须包含：

- 问题编号：`YYYYMMDD-NN`
- 问题现象
- 发生环境
- 问题原因
- 解决方法
- 验证证据
- 涉及文件
- 后续注意事项

### 3. 引用

后续编写开发方案时，在“历史问题参考”章节引用相关问题编号。

## 验证

- [ ] 问题编号符合 `YYYYMMDD-NN`。
- [ ] 条目具有未来复用价值，不是工作流水账。
- [ ] 必填章节全部填写。
- [ ] 解决方法已验证；未完全确认的原因已明确标注。
- [ ] 没有重复记录已有问题。
