# 复用脚本

## 分类

先查找现有脚本或工具能否完成任务，再判断是否需要长期维护：

- 已有重复执行需求、明确后续使用场景，或用户要求保留时，复用、扩展或创建项目脚本。
- 只服务于当前一次性比对、排查或转换，且没有明确后续用途时，可用内联命令或临时脚本，不为形式创建永久文件。

行数、路径数量、是否处理真实数据或是否运行检查，都不单独证明复用价值。用途尚不明确时先采用满足本次目标的最小方式，出现实际复用需求后再沉淀。只读任务仍遵守只读边界，不因本技能创建项目文件。

## 工作流

1. 先找现有脚本目录：`scripts/`、`tools/`、`bin/`、`utils/`、包内脚本目录。
2. 复用或扩展现有脚本风格，不另起无关框架。
3. 确需长期维护时，按现有调用方式提供所需参数；独立运行工具再提供 CLI，优先使用标准库。
4. 让需要变化的路径和选项可配置，避免隐藏的本机路径依赖。
5. 按任务需要保证可复现输出，明确生成文件和覆盖行为。
6. 对新增或改变的脚本执行与风险相匹配的代表性验证；外部写入、设备或破坏性动作仍按授权执行，不为验证自动运行这些动作。
7. 交付实际命令、结果和限制；保留了项目脚本时再说明其路径与复用方法。

## 验证

- [ ] 已优先检查现有工具，并说明持久化的实际用途。
- [ ] 需要保留的脚本位于项目约定目录，接口与使用场景匹配。
- [ ] 验证覆盖本次改变的行为；未执行的动作及限制如实说明。
