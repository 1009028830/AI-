# 复用脚本

## 分类

写任何非平凡脚本前，先分类：

- 一次性：少于约 20 行、无复杂解析、无复用价值的临时检查，可 inline 执行。
- 可复用：解析真实项目数据、生成报告、转换文件、运行检查、包含多个输入输出路径、或用户要求保留，必须沉淀为项目脚本。

不确定时，如果后续可能重复运行，按可复用处理。

## 工作流

1. 先找现有脚本目录：`scripts/`、`tools/`、`bin/`、`utils/`、包内脚本目录。
2. 复用或扩展现有脚本风格，不另起无关框架。
3. 为可复用脚本提供 CLI，优先使用标准库参数解析。
4. 避免隐藏硬编码路径。关键路径必须能通过参数覆盖。
5. 输出要可复现：稳定文件名、排序结果、明确生成文件清单。
6. 用代表性命令实际运行脚本。
7. 交付时说明脚本路径、命令和输出。

## 验证

- [ ] 已判断脚本是一次性还是可复用。
- [ ] 可复用脚本已放入项目持久目录。
- [ ] 提供了 CLI 参数。
- [ ] 已实际运行代表性命令。
