# 最小改动实现

## 流程

### 1. 重新读取执行边界

L1 读取 micro-plan；L2/L3 读取已有授权覆盖的方案，不因阶段切换重复审批。核对：

- 新增、修改、不修改文件。
- 实现流程和模块职责。
- 测试和验证要求。

方案缺失且会改变结果、成本或风险的关键细节先澄清；其余在已授权范围内采用合理假设并说明。不能自行扩大范围或增加未授权外部/设备动作。

### 2. 按薄垂直切片实现

- 一次只实现一个可验证切片。
- 只修改计划列出的文件。
- 不添加未确认功能、接口、字段、依赖或配置项。
- 不做无关重构。
- 优先复用项目已有模式、工具和测试。
- 保持每个文件职责清晰。
- 发现新问题时，按 `problem-tracking` 记录到 `docs/development_memory.md`。
- 每个有行为变化的切片先做相关编译/基础检查，再验证行为；纯文案核对差异和引用。切片迭代只修复失败项，不每次执行完整审查。后续交付复用有效结果，失败时停止扩展并定位根因。

### 3. 合并到最终集中审查

相关编译和功能验证通过后，按 `verification-and-review` 对本次改动集中审查一次。以下事项并入该轮审查，不另启一轮“自查”；小型修改仅核对适用项：

- 文件职责清楚，没有把无关逻辑混在一起。
- 新增公共入口、脚本或配置有必要说明。
- 错误路径可读，失败信息能帮助定位。
- 没有覆盖或回退用户已有改动。
- diff 只包含当前目标，且能说明如何回退。

## 验证

- [ ] 只改了已授权范围和方案内的文件；问题记录例外已说明。
- [ ] 没有添加方案外功能。
- [ ] 使用了最小必要改动。
- [ ] 每个切片均有验证证据。
- [ ] 小型修改凭聚焦证据直接交付；标准或高风险修改按需交给 `verification-and-review` 补齐相关检查，已有有效结果不重跑。
