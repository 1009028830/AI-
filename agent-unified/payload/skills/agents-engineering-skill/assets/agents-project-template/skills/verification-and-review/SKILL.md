# 验证与审查

## 1. 生成验证矩阵

| 变更/风险 | 验证方法 | 预期 | 实际 | 环境 | 结论 |
|---|---|---|---|---|---|
| [项目] | [命令/操作] | [标准] | [证据] | [本地/沙箱/目标] | 通过/失败/未验证 |

先运行最小相关检查；L2/L3 再按影响范围运行回归。不要重复昂贵且与变更无关的全量测试。

## 2. 处理失败

测试失败时：

1. 保存原始错误。
2. 判断是本次回归、已有失败、环境限制还是测试本身问题。
3. 修复根因后重跑受影响检查。
4. 未解决失败不得写成通过。

## 3. 五轴审查

- **正确性：** 验收、边界、错误路径、回归。
- **可读性：** 命名、控制流、重复、注释与复杂度。
- **架构：** 分层、依赖方向、接口与范围纪律。
- **安全：** 输入、权限、密钥、日志、资源与依赖。
- **性能：** 无界操作、阻塞、内存、I/O；没有基线时不宣称优化。

问题按 `阻断 / 重要 / 建议` 分类，给出具体文件与修复方向。

## 4. 对照完成标准

读取 `references/definition-of-done.md`。未满足项要么修复，要么明确列为未完成、未验证或已接受风险。
