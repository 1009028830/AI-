# 上下文加载

## 流程

1. 读取根与目标路径最近的 AGENTS 规则。
2. 读取 `docs/agent/knowledge-map.md`，确定当前主题的权威来源。
3. 读取任务入口、公共接口、调用方、相关测试和历史问题。
4. 只在当前步骤需要时读取详细规范、协议或长参考。
5. 记录事实、推断、冲突和未知项；不要混为同一结论。

## 上下文包

在方案或分析中形成简短上下文包：

```markdown
### 目标
[本次要回答或改变什么]

### 权威来源
- `path`: 为什么相关

### 当前行为
- [由源码/测试确认的事实]

### 约束与冲突
- [适用规则、冲突、未知项]

### 验证入口
- [命令或手动步骤]
```

## 规则

- 不一次加载所有技能、规范和历史方案。
- 历史方案不是当前事实，除非代码或现行文档确认。
- 搜索命中是线索，不是证据；关键路径必须阅读全文或源码。
- 外部资料可能变化时按 `source-verification` 查官方来源。

## 验证

- [ ] 上下文覆盖目标、入口、调用方、测试和适用规则。
- [ ] 每个关键事实有来源。
- [ ] 未加载与任务无关的大量资料。
- [ ] 冲突与未知项已显式列出。
