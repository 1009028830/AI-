# 交付检查清单

## 流程

### 1. 检查 Definition of Done

读取：

```text
references/definition-of-done.md
```

确认所有适用项已有证据，未满足项必须成为交付中的风险或未完成项。

### 2. 汇总验证

按方案运行可用验证：

- 构建或静态检查。
- 单元测试或冒烟测试。
- 关键功能验证。
- 回归风险检查。

无法验证的内容要明确说明原因。

不要重复运行无必要的昂贵测试；使用 `verification-and-review` 已记录的最新结果。

### 3. 编写交付说明

使用：

```text
references/delivery-format.md
```

交付说明必须包含：

- 修改目标。
- 修改文件。
- 实际完成内容。
- 未做内容 / 未验证内容。
- 问题记录更新。
- 构建方法。
- 测试方法。
- 注意事项。
- 风险与回退方法。

### 4. 最终检查

```text
实现
  [ ] 只修改了方案范围内文件；问题记录例外已说明
  [ ] 没有添加未确认功能
  [ ] 没有回退用户已有改动
测试
  [ ] 已运行可用测试
  [ ] 无法运行的测试已说明原因
文档
  [ ] 交付说明列出所有修改文件
  [ ] 明确说明未做和未验证内容
问题记录
  [ ] 新问题已记录或明确说明无更新
风险
  [ ] 已说明回退方法和目标环境验证边界
```

## 验证

- [ ] 已给出具体测试命令或验证证据。
- [ ] 已区分已验证和未验证。
- [ ] 已说明 `docs/development_memory.md` 是否更新。
