# Linux 应用开发与诊断

针对用户态程序建立源码、构建、运行环境与证据之间的对应关系；不将 Linux 内核代码规范直接套用到应用层。

## 确定构建与运行边界

- 识别宿主、目标架构、发行版、libc、编译器、sysroot、语言标准与项目构建入口。glibc/musl、软硬浮点、32/64 位和 ABI 差异按实际目标核对。
- 区分宿主工具、交叉编译产物、容器/WSL 与真实部署设备；动态库和头文件来自同一目标环境，不能把宿主库混入目标链接。
- 阅读服务启动方式、配置、设备路径、运行用户、工作目录与日志入口。不得默认 systemd、root、sudo、网络或设备节点可用。
- 诊断先取得错误、可重现输入和匹配版本的程序/符号；读取现有上下文可以继续，改变系统服务或生产运行状态另按任务授权处理。

## 实现与审查清单

| 边界 | 检查内容 |
| --- | --- |
| 文件描述符与内存 | 唯一所有者、借用期、关闭顺序、失败释放；C++ 优先用项目已有 RAII 封装 |
| 线程与同步 | 锁序、共享状态、等待谓词、退出/取消、回调生命周期；避免持锁进行不可控 I/O |
| 信号 | 区分线程安全与异步信号安全；处理器只做安全的最小动作，复杂清理转交正常执行上下文 |
| 系统 I/O | 短读写、EOF、EINTR/EAGAIN、非阻塞就绪、断开与超时；不统一重试所有调用，按进度与幂等性处理 |
| 时间 | 相对超时与截止时间、时钟来源、溢出及墙钟调整影响；不把系统时间跳变误当设备响应延迟 |
| 外部输入 | 长度、端序、编码、数值范围、协议状态与配置校验；日志保留上下文并脱敏 |
| 兼容与部署 | 依赖库、符号、ABI、配置格式、权限、可执行路径与回退；不直接覆盖正在服务的产物 |

POSIX 接口与 Linux 扩展分别核实。pthread 等接口的返回错误约定可能不同于 errno，须按具体函数检查。

## 按证据选择验证

1. 复用现有构建、单元测试和静态检查；交叉分析前验证编译数据库与目标宏、头文件、sysroot 一致。
2. 对与变更相关的正常、超时、断开、异常输入和退出路径测试；能脱离设备的逻辑在宿主测试，不能外推为目标 I/O 已通过。
3. 崩溃用匹配可执行文件和调试符号分析 core/backtrace；阻塞问题按需使用线程栈、GDB 或 strace。附加调试和追踪可能改变时序或暂停服务，执行范围应符合已有授权。
4. Sanitizer、覆盖率与性能工具仅在目标/构建支持且能回答问题时启用；保留基线和最小复现，不为了完整性运行无关全量检查。
5. 授权部署时验证产物架构、依赖、权限与配置，保留旧版本并按项目方式切换；失败则按已定义条件回退。未接触目标设备时明确待执行的目标冒烟用例。

交付包括运行环境、根因或变更依据、实际命令与结果、资源/并发影响、部署回退和未验证项；普通只读分析不自动变成部署任务。
