# 车载嵌入式工程检查项

版本 1.0.0；编写/来源查询日期：2026-10-16。以下 A 编号是本库原创工程检查项，**不是任何标准的条款编号或逐条转述**。按项目适用性采用，标准来源和读取深度见 [规范目录](standards.md)。每条结论应指向需求、代码、配置或测试证据。

## 需求、架构与供应链接口

- **A01 适用性**：记录车型、市场、开发/量产阶段、合同标准版次及修改单；将强制要求、客户要求、内部建议分开。不把某市场规定自动推广到所有车辆。
- **A02 追溯**：控制需求含输入、输出、状态前提、精度、时限和异常语义；把安全需求关联到实现与验证，变更时检查受影响的接口、标定和测试。
- **A03 软硬件接口**：核对引脚有效电平、上拉/下拉、上电默认态、复位态、看门狗、供电域、SPI 模式和 ADC 量程；软件初始化前的输出状态也纳入设计。
- **A04 AUTOSAR 边界**：确认 Classic/Adaptive/自研栈和具体 release；Classic 按应用、RTE、BSW/MCAL 约定接入，核对供应商模块及配置兼容。不能把层次图当成已有实现。
- **A05 配置一致性**：ARXML、DBC/LDF、ODX、A2L、标定、生成器版本与 ECU 变体绑定；生成结果可重现，禁止只改生成代码掩盖配置问题。
- **A06 供应商假设**：安全手册中的使用假设、诊断周期、初始化/自检、失效响应逐项落实；芯片的车规等级或安全能力不直接赋予整机相同等级。

## C/C++、内存与执行模型

- **A07 语言与工具**：锁定 C/C++ 标准、编译器版本、优化选项、ABI、库和规则集；MISRA 偏离需理由、适用范围、风险和批准记录，不能用全局 suppress 掩盖问题。
- **A08 整数与定点**：在扩展类型中计算，转换前检查范围；明确饱和、截断、舍入和负数规则。覆盖乘加溢出、除零、移位、计数器回绕和无效哨兵值。
- **A09 报文布局**：显式处理端序、位序、对齐和长度，不把接收缓冲区强转为带填充的结构体；位域、浮点线格式和有符号右移按实现约束评审。
- **A10 资源上界**：依据实时性和安全约束决定动态分配/递归策略；证明栈、堆、队列、句柄和日志上界。禁止仅凭一次运行的栈高水位断言最坏情况充足。
- **A11 并发**：区分原子性、可见性与顺序；`volatile` 不替代原子操作、锁或内存屏障。核对多核、DMA、cache 及外设寄存器的访问语义。
- **A12 ISR**：确认 ISR 可调用 API、嵌套优先级和最长执行时间；耗时工作有界下放，核对中断清除顺序、共享缓冲区和中断风暴处置。
- **A13 调度**：记录周期、抖动、截止期、抢占、阻塞和优先级反转；在代表性的峰值负载下测量并分析最坏响应时间，不以平均 CPU 占用代替截止期证据。
- **A14 时基**：超时使用适当单调时钟，处理 tick 回绕、时钟漂移、睡眠和复位；网络同步时间与本地控制时基明确转换及失步行为。
- **A15 看门狗**：监督关键任务进展和时序，喂狗不能只证明某个定时器仍运行；保存复位原因，验证启动循环、故障锁定与恢复条件。
- **A16 存储**：NvM/Flash 写入考虑磨损、掉电原子性、版本、校验和迁移；区分数据完整性 CRC 与抗篡改认证，损坏后的默认值需满足系统安全约束。

## 车载网络与电源状态

- **A17 CAN/CAN FD**：核对 ID/格式、DLC、仲裁/数据段位速率、BRS、收发器能力、终端和过滤；总线负载分析覆盖故障与诊断流量，不能从 CAN FD 软件支持推断硬件支持。
- **A18 信号契约**：每个控制信号定义单位、比例、偏移、范围、有效标志、更新周期和最大年龄；陈旧值、缺帧、越界值不能默认为 0 或永久沿用。
- **A19 E2E**：按所选 profile 和 OEM 定义核对计数器、Data ID、CRC、序列窗口及启动同步；测试丢失、重复、乱序、损坏和发送方复位。不要自行创造兼容性不明的 E2E 格式。
- **A20 Bus-off**：按网络管理约定实施恢复次数、等待、故障上报和降级；防止无限重连/重发使系统在故障总线上持续放大流量。
- **A21 LIN/J1939**：LIN 核对主节点调度表、校验类型、睡眠唤醒和从节点响应；J1939 核对地址声明、PGN/SPN、传输模式与 OEM 扩展，不能套用普通 CAN 帧假设。
- **A22 以太网**：核对 VLAN、IP、路由、SOME/IP 服务版本/发现、订阅生存期及队列；TSN/PTP 仅在项目实际采用时验证同步误差、丢同步和负载，不默认所有网络都有确定性。
- **A23 休眠唤醒**：识别唤醒源和保持条件，核对网络管理、诊断保活、日志落盘与供电关闭顺序；测试伪唤醒、频繁唤醒和静态电流，不能用软件 sleep 成功代表整机休眠。

## 诊断、Bootloader 与升级

- **A24 UDS 基线**：按合同版次核对寻址、会话、服务/子功能、NRC、P2/P2*、S3、TesterPresent 和并发客户端。新标准不能自动改变既有 DID、DTC 或 OEM 服务语义。
- **A25 ISO-TP/DoIP**：ISO-TP 核对地址模式、分段长度、流控 BS/STmin、序号、超时和内存上界；DoIP 核对发现、路由激活、连接状态、断连和安全配置，传输确认不等于 UDS 成功。
- **A26 DTC 生命周期**：定义检测、去抖、pending/confirmed、冻结帧、老化、清除和存储条件；故障清除请求不能直接解除仍然存在的保护或抹掉必须保留的证据。
- **A27 敏感服务**：诊断权限、会话前提、车辆状态和失败计数都在 ECU 端校验；生产固件移除测试后门，日志不写密钥或安全访问材料。
- **A28 启动可信链**：依据项目安全架构核对签名、信任根、版本策略、调试生命周期和密钥更新；CRC 或哈希比较本身不能证明固件来自可信发布者。
- **A29 升级事务**：覆盖擦除/写入/校验/切换各阶段掉电、欠压、空间不足和多 ECU 版本不一致；保证恢复路径，防回滚策略与可恢复性协同设计。
- **A30 标定和量产**：安全参数受范围、完整性、身份和变体检查保护；EOL 烧录、序列号、密钥注入、标定和返修有独立记录与权限，不把开发配置直接投产。

## 安全、验证和交付

- **A31 功能安全**：依据已批准 HARA/安全概念核对监控、冗余、自由干扰、故障检测与反应时间；ASIL 分解和独立性必须有相应分析，不能靠模块拆分自行宣布满足。
- **A32 网络安全**：按资产、入口、信任边界和攻击路径开展 TARA；权限、密钥生命周期、诊断/更新、日志和漏洞响应形成闭环，认证失效后的行为不能破坏安全目标。
- **A33 EMC 与环境**：把供电跌落、瞬态、温度、振动和 EMC 测试中的软件功能状态及恢复判据写入测试计划；CISPR 25 发射结果不覆盖抗扰度或全部电气安全。
- **A34 分层验证**：单元/集成、SIL、目标编译、HIL、台架和整车分层记录；选定的覆盖率目标、MC/DC 及结构覆盖缺口由安全计划决定，不把达到数字等同于需求正确。
- **A35 故障注入**：覆盖超时、损坏/陈旧输入、任务超期、复位、存储损坏和失电；在授权环境内实施，测试要有预期检测、处置、恢复和原始观测。
- **A36 发布追溯**：关联需求、设计、代码、供应商版本、SBOM、标定、构建产物、测试和偏离批准；记录已知问题及残余风险，保持被测和交付版本一致。
