# STM32 固件开发与评审

将当前芯片、工程配置和硬件约束对应到实现与验证。普通只读问题直接分析；开发请求在已有授权内实施，缺少硬件时继续可完成的源码、构建和测试工作。

## 先确定实际目标

- 从工程识别完整芯片型号、板卡修订、Cortex-M 内核、Flash/RAM 布局、启动方式、外部晶振与关键外设；未提供的项目事实标为未知，不按经验补造。
- 查 `.ioc`、启动文件、链接脚本、工具链文件、Cube 固件包、HAL/LL 和 CMSIS 版本、RTOS 配置及项目已有构建入口。Keil、IAR、CubeIDE 和 CMake 工程不能假设互换。
- 对当前问题读取对应型号的 Datasheet、Reference Manual、Programming Manual、Errata 及相关原理图页；先用项目固定版本，移动在线入口仅用于定位。
- 区分生成代码、厂商库、自有 BSP 和业务逻辑。编辑前确认生成区域保留机制，不因添加功能全量重新生成工程或替换 HAL。

## 按变更检查

| 涉及内容 | 必须核对的约束 |
| --- | --- |
| 启动与时钟 | 向量表、启动地址、系统时钟与外设时钟、Flash 等待周期、初始化顺序；参数来自当前型号资料 |
| 内存与链接 | 段地址、栈/堆、对齐、启动复制与清零、引导程序边界；结合 map 文件检查容量和布局 |
| 中断与 RTOS | ISR 调用限制、优先级分组、RTOS 可调用优先级范围、临界区与任务通知；不在 ISR 中执行无界等待 |
| DMA 与缓存 | 控制器可访问的 RAM、传输宽度、缓冲区生命周期及对齐；仅对有缓存目标核对 cache line、维护范围和 CPU/DMA 所有权交接 |
| 驱动与业务 | HAL/LL 状态检查、超时、重入和总线互斥、恢复状态机；不用示例死循环替代产品故障处理 |
| C/C++ | 整数范围、边界、寄存器宽度、资源所有权；volatile 不替代同步，异常/RTTI/动态内存按项目约束使用 |

仅检查被当前任务影响的项。涉及寄存器、屏障、缓存和中断语义时回到该型号资料及实际 SDK 实现，不把某个系列的修复套用于所有 STM32。

## 实施与验证

1. 复用项目实际构建命令。跨文件符号查询或静态分析前核对 CPU、FPU、ABI、宏、头文件与 `compile_commands.json`；宿主默认参数不能代表固件。
2. 修改自有逻辑并保留厂商/生成边界。对协议编解码、状态机、计算等可分离逻辑执行宿主测试，补充与变更相关的边界和失败路径。
3. 在匹配工具链下构建，记录命令、配置、编译警告及必要的 map/尺寸变化。已有工程工具箱可提供分析工具；缺失时说明缺项，不擅自安装另一个 SDK。
4. 有目标板且任务授权覆盖烧录/运行时，核对探针、目标序列号、固件、地址和恢复方式；记录复位、启动、外设反馈、栈/堆或时序证据。影响执行器、保护参数或电源状态的动作仍需相应明确授权。
5. 无目标板时交付构建和软件验证结果、待执行的板上用例及判定条件，不宣称硬件通过。出现不可恢复错误或安全边界异常，停止相关动作并保留诊断信息。

交付说明具体目标与版本、修改范围、实际执行的检查、固件/日志位置、未覆盖项；仅在适用时给烧录回退步骤。合规要求按合同指定标准、工具覆盖和偏离记录建立证据，不能将静态检查通过称为 MISRA 全面合规。

## 资料入口

资料整理日期：2026-10-15。以下为入口；具体工程须固定型号和版本。规则为工程检查建议，不替代厂商手册。

- [CMSIS-Core Cortex-M / Arm](https://arm-software.github.io/CMSIS_6/latest/Core/index.html)：启动、异常、核心寄存器及访问接口；本次在线核对。

- 型号特有 RM/PM/Errata 由当前项目芯片型号从 ST 官方入口定位，不预填其他型号链接。
