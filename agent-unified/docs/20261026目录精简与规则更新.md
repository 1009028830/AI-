# 2026-10-26 目录精简与规则更新

本次目标是减少重复流程和旧入口干扰，保留公开源码、个人恢复包、本机安装及原始架构资料各自的用途。普通提交、推送和 PR 的既有边界保持不变。

## 规则变化

- 风险等级按行为和影响判断，不因文件数量机械升级。普通 L2 可使用聊天短方案；跨模块接口、高风险、跨会话协作或明确要求时才保存必要方案。
- 一次性检查不再因行数、多路径或真实数据而强制生成永久脚本。可复用自动化仍优先使用已有脚本。
- 全局验证要求集中维护，沿用“编译/基础检查 → 相关功能验证 → 一轮集中审查”，修复只重查受影响部分。
- 正式 Word 的完整版式要求迁至[按需参考](../payload/skills/agents-engineering-skill/references/正式文档版式规范.md)，随技能安装；仓库文档和 Git 提交说明不因“提交/发布”字样转为 Word。
- STM32 工作流先构建或基础检查，再执行相关功能验证；缺少目标工具链时保留未验证状态。
- 新项目统一使用现行工程模板。早期 demo 和两份长规范停止作为推荐入口，保留的旧正文注明历史用途。

## 文件与恢复边界

公开源只保存适合公开分发的内容，个人恢复源保留离线资产和额外技能；不同 Git 工作树不能当成普通重复目录删除。

资产制作改为校验正式锁定成品或显式导入/重制，见[资产维护说明](资产维护.md)。旧工具目录和暂存区不再充当隐式输入；这不等于公开 Git 克隆包含离线资源。

清理输出目录前，应先归位清单维护脚本并保留权威 Excel。DeepSeek 协作原型和 Visio 架构源文件继续保留。历史验证按日期解释，不能用旧结果代替当前版本或真实设备验收。
