# Git 协作规则整合

- 日期：2026-10-26
- 状态：规则已实施并验证；同步与归档的最终结果见迁移包侧文件。
- 级别：L2，规则行为变化，不修改版本控制工具或恢复引擎。
- 授权：用户要求依据《Gitee版本管理与测试方案.md》更新提交规则；覆盖规则编辑、本机同步和既有迁移包更新。无需再次确认同一范围。

## 目标与依据

把用户方案的 Git Flow、Conventional Commits、PR 评审、分层验证、Tag/Release 与回退要求整理为跨 Windows/Linux、GitHub/Gitee 的可执行指导。原文保留，不把其中的示例命令当作当次远端操作授权。

现有规则已经支持按影响验证、已有授权复用及一轮集中审查。本次补充版本协作入口，不增加每次提交的全量回归。

## 实施范围

- 全局规则源 `config/AGENTS.md`：简短默认要求及详细入口。
- 工程技能 `SKILL.md`、项目模板 `AGENTS.md`：按任务读取 Git 协作参考。
- 项目模板 `references/git-collaboration.md`：唯一详细正文，随技能与项目初始化复制。
- 公开仓库根 AGENTS/README、恢复包 README：导航与适用边界。
- 同步本机对应文件、个人包源目录及受管技能文件哈希；重建并校验完整个人 ZIP。
- 不改原始方案、业务代码、恢复引擎、旧项目快照和账号配置；不配置远端保护、CI、Git hooks，不执行提交、推送、合并、Tag 或发布。
- 若实施中出现需要沉淀的真实问题，可按既有约定补充问题记录；普通过程不另建问题库。

## 整合原则

- 团队协作参考 Git Flow；既有分支模型和实际主干名称优先。按用户后续明确要求，个人工作默认提交/推送，只有协作或明确要求时创建 PR，不自动创建 develop 或重写历史。
- 修正全历史提交扫描、提交类型/发版触发矛盾、跳过 LFS 上传及无条件回退/删除示例。
- GitHub/Gitee 的套餐、权限、CI 语法、Issue 关闭和 LFS 限额按当前平台核实，不固化成全局事实。
- 人工审批、CI 结果与 Agent 审查分别记录，保持安全/发布授权边界。

## 验证与回退

运行工程技能和模板的结构/链接验证；静态核对普通提交、PR、新分支、hotfix、发版、LFS、已有授权和只读任务场景。脚本未变化，不重复运行安装器或业务全量测试。

同步前后核对文件哈希，冲突不覆盖；更新后的包使用既有构建与 ZIP 校验入口，并执行恢复入口 `--verify`。不声称 Linux 新机恢复或真实硬件验收。

公开源保留 Git 基线，目标同步前记录原哈希；只在内容匹配时同步。归档使用新文件名，验证成功前保留已验证包。待确认事项：无；远端设置与发布不在本次执行范围。

## 个人提交方式补充

用户随后明确：个人提交不创建 PR，只有多人协作或明确要求时使用 PR。全局规则、技能、项目模板和参考正文已据此调整；遇到强制 PR 门禁时说明限制并取得后续选择，不绕过保护。本次提交目标仍为已有 GitHub `main`，使用正常快进推送，不合并 PR、不强推、不发版。参考正文更新为 v1.1，重新执行受影响的结构/链接校验并同步本机和迁移包；未变化的初始化器预览与其他验证证据继续复用。
