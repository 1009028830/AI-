# 离线资产维护

正式可复用输入位于 `assets/`、`locks/` 和 `config/*-assets.json`。它们不依赖旧工具安装目录或 `staging/`；普通规则更新只需重新生成迁移包，不需要重装所有工具。公开源码没有这些大型成品，Git 克隆不能替代完整离线包。

在本包目录执行以下命令，默认只读预览；`--verify` 会核对全部成品的 SHA256、大小和声明的归档入口：

```text
python scripts/prepare_native.py
python scripts/prepare_native.py --verify
python scripts/package_node.py --verify
```

可以用 `--root PATH` 指向另一份完整包；不会修改该包的安装环境。缺失或损坏的成品明确报错，不生成空包，也不移除 GDB、LLVM 或未选工具组的记录。需要从完整包或成品缓存补回文件时：

```text
python scripts/prepare_native.py --apply --source-dir PATH
python scripts/package_node.py --apply --source-dir PATH
```

来源可以是另一完整包根目录，或直接包含对应成品文件的缓存目录。导入必须匹配现有清单的哈希，先校验全部候选，再提交文件；不会更新清单以接受未知成品。原生脚本不再负责从旧安装目录一次性提取程序，也不会自动下载上游安装器。更换原生版本或制作新的精简包需单独审查来源、许可证、入口及平台验证，再更新相应锁定记录。

Node 工具需要重制时，先在显式工作目录按正式 `locks/<组名>-package.json` 和 `locks/<组名>-package-lock.json` 准备依赖。仅在已授权联网安装时运行匹配 Node/npm 的 `npm ci --ignore-scripts`；本脚本不会代办安装或审计。随后显式选择工具组：

```text
python scripts/package_node.py --source bruno=PATH
python scripts/package_node.py --apply --source bruno=PATH
```

可以重复 `--source`。源根仅接受 `package.json`、`package-lock.json`、`node_modules/` 和明确的 README、LICENSE、COPYING、NOTICE 说明/许可文件；发现 `.npmrc`、`.env` 或其他未允许内容时拒绝重制并报告文件名，避免误选业务项目或带入凭据。该限制只针对源根，不剔除 `node_modules` 内合法包的许可和数据。

源 package/lock 必须与正式锁一致，且彼此的依赖约束一致；缺入口、未审核链接和不允许的原生模块会阻止提交。原有 Oracle Thin-only 排除边界仅对已声明该模式的工具组生效。重制前须确认源目录已按锁安装并完成相关功能验证；文件检查本身不证明依赖内容完整或工具功能正确。成功后仅更新选中归档的哈希和大小，保留其他记录及来源信息；普通异常会恢复旧归档与清单。进程被强制终止或断电仍需先检查残留 `.part`/`.previous` 和锁定哈希，再决定恢复。

运行时和 Python 资源更新另用 `prepare_assets.py`，默认同样只读。明确执行 `--apply` 后才会按所选模式下载、解析锁或运行验证，例如：

```text
python scripts/prepare_assets.py --mode runtimes --apply
```

该步骤用于资源维护，不是常规规则编辑的必要步骤。工具版本更新按现有来源、哈希和平台验证流程处理；已准备好的成品仍优先复用。更改任何发布文件后，重新执行现有 `build_release.py` 和 `verify_release.py` 更新并校验迁移包，不能把旧清单用于新内容。
